Based on the `20_env.out` file, I have incredible news and one major architectural catch.

### The Good News: Bob is Fixed!

When we look at the few times Bob was actually given a chance to play in this 8-hour run, your previous math fixes worked flawlessly:

* **Bob's Success Rate (SR)** hovered between **45% and 66%**!
* **Bob's ABC Loss** was completely stable.
* Bob is no longer the bottleneck; the environment math is completely healthy.

### The Bad News: Alice is Paralyzed

I ran a parser over your 31,000-line log file. Over the course of 8 hours:

* Alice generated a **Valid Goal**: 33 times
* Alice generated an **Invalid Goal**: 5,475 times

In almost all 5,475 failures, the log prints exactly: `Moved: 0.027m < 0.01m threshold`.
Why exactly `0.027m`? Because Alice is literally standing still. The object is spawning slightly in the air, dropping to the table via gravity, and that drop distance is exactly `0.027m`.

### The Root Cause: "Experience Deletion"

In your previous 4-environment run, Alice got lucky—her random neural network initialization caused her to accidentally bump the blocks past the 5cm threshold, which gave her a reward and bootstrapped her learning.

In this 20-environment run, her random initialization caused her to just hover. Because she failed to reach the threshold, the environment triggered an "Invalid Goal" reset (`dones=True`).

Here is the fatal flaw in `train.py`:
When Bob finishes a goal, Alice's data is correctly pushed to her PPO storage. **But when the environment resets due to an Alice failure (Invalid Goal, Out of Bounds), the code simply deletes her trajectory.**

```python
        # Current logic in train.py
        # Safety: Clear Alice buffers for any envs that reset (dones=True)
        if dones.any():
            reset_ids = torch.where(dones)[0]
            alice_step_counts[reset_ids] = 0 # <--- DELETES THE DATA!

```

Because her failed attempts are deleted instead of being passed to PPO, **Alice never receives a gradient penalty for standing still.** She doesn't know she is failing; to her neural network, those episodes never existed.

### The Fix Plan

You must log Alice's failures into her PPO buffer so her Value Network learns that "standing still results in 0 reward," which will create a negative advantage and force her to explore.

Open `train.py`, scroll down to around line 465, and replace the old `# Safety: Clear Alice buffers` block with this updated logic:

```python
        # --- HANDLE ALICE FAILURES (OOB, Invalid Goals, Collisions) ---
        # If the environment reset (dones=True) but alice_step_counts > 0,
        # it means Alice failed to set a valid goal and the episode was aborted.
        # We MUST push these failures to her storage so she learns not to do them!
        if dones.any():
            reset_ids = torch.where(dones)[0]
            
            for idx in reset_ids:
                env_id = idx.item()
                count = alice_step_counts[env_id].item()
                
                # If count is > 0, it's an Alice failure (Bob completions already set count to 0)
                if count > 0:
                    # Extract slices
                    tr_obs = alice_obs_log[env_id, :count]
                    tr_act = alice_act_log[env_id, :count]
                    
                    with torch.no_grad():
                        _, tr_logprob, tr_val, tr_mu, tr_sigma = alice_ppo.actor_critic.evaluate(tr_obs, None, tr_act)
                    
                    # Apply any validity penalties (e.g., -3 for Out-of-Bounds)
                    validity_bonus_val = alice_validity_buffer[env_id].item()
                    alice_validity_buffer[env_id] = 0.0  # Reset
                    
                    tr_rew = torch.zeros(count, device=env.device)
                    tr_rew[-1] += validity_bonus_val  # Usually 0.0 or penalty
                    
                    tr_done = torch.zeros(count, device=env.device)
                    tr_done[-1] = 1.0
                    
                    valid_mask = torch.zeros(env.num_envs, 1, device=env.device)
                    valid_mask[env_id] = 1.0
                    
                    for t in range(count):
                        _o = torch.zeros(env.num_envs, env.alice_obs_dim, device=env.device); _o[env_id] = tr_obs[t]
                        _a = torch.zeros(env.num_envs, *env.action_space.shape, device=env.device); _a[env_id] = tr_act[t]
                        _v = torch.zeros(env.num_envs, 1, device=env.device); _v[env_id] = tr_val[t]
                        _lp = torch.zeros(env.num_envs, 1, device=env.device); _lp[env_id] = tr_logprob[t]
                        _m = torch.zeros_like(actions); _m[env_id] = tr_mu[t]
                        _s = torch.zeros_like(actions); _s[env_id] = tr_sigma[t]
                        _r = torch.zeros(env.num_envs, device=env.device); _r[env_id] = tr_rew[t]
                        _d = torch.zeros(env.num_envs, device=env.device); _d[env_id] = tr_done[t]
                        
                        alice_ppo.storage.add_transitions(_o, _o, _a, _r, _d, _v, _lp, _m, _s, valid_mask)
                    
                    alice_rew_buf.append(tr_rew.sum().item())
                    perform_alice_update()
            
            # Clear counters for all reset envs
            alice_step_counts[reset_ids] = 0

```

Once this is applied, Alice will actually feel the sting of failure and begin thrashing her arms to find the blocks. Because we know Bob is mathematically fixed and capable of reaching a 66% SR, they will immediately begin their adversarial spiral!
